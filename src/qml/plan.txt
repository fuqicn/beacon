修复目标：整合包下载分段数从 8 片回退到 4 片（已完成）
文件：third_party/minecraft-launcher-kernel/libmcbase/src/mc_download_qt.cpp
  当前: static int g_max_pieces = 8;
  目标: static int g_max_pieces = 4;   → 已完成
  原因：用户实测 8 片并发下载不如 4 片稳定；mod.mcimirror.top 在 HTTP/1.1 下 8 并发可能触发限流/慢源中止。

额外发现并修复：ModManager.cpp 在入队时会把分段数强制改回 8（覆盖内核默认值），已同步改为 4。

附加修复：取消任务时 UI 卡住问题（已完成）
文件：src/kernel/managers/ModpackManager.cpp / .h
  原因：stopWorkerThread() 在主线程上 for 循环 m_workerThread->wait(200) 最多 30 秒，
        取消窗口内整个 GUI 冻结。
  方案：改为非阻塞协作式取消——
    - stopWorkerThread() 只设取消标志+quit，立即返回，不再 wait。
    - 线程真正退出时由 QThread::finished 处理器回收线程、配对释放全局取消引用、清除 busy。
    - cancelAll() 置状态"取消中..."；busy 保持 true 直到线程退出，防止取消窗口内新装。
    - errorOccurred 处理器在取消请求下不再发错误/清 busy（交给 finished 处理器）。
    - 析构函数保留有界 5s 等待（关停时允许阻塞），超时则解除父子关系避免析构正在运行的线程。
  配对保证：新增 m_cancelRequested 标志确保 refcount 型全局取消标志只配对一次。

验证：构建通过；冒烟运行 8s 无 QML 错误、无残留进程。
