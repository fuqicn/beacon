内存优化 TODO
==============================

现状基线（空闲 8s 后，Win11 build 26200，Qt 6.11.1）
  PrivateBytes : 210.6 MB
  WorkingSet   : 230.5 MB
  Threads      : 22
  Handles      : 926

结论：约 120–150MB 是 Qt Quick + D3D 运行时的固有成本，不可减；
可优化的是其余部分。下列所有方案均不影响美观 / 动画 / 功能。

---------------------------------------------------------------
A 组：低风险白捡（约 5–15MB）
---------------------------------------------------------------
[x] 1. 移除 Qt6::Widgets
     - CMakeLists.txt:9 的 find_package 和 target_link_libraries 里删掉 Qt6::Widgets
     - 已验证全工程 src 无任何 QWidget/QApplication/QMainWindow 使用
     - 收益：Qt6Widgets.dll 及其私有数据段不加载
     - 已做：exe 导入表已无 Qt6Widgets.dll（objdump -p 验证）

[x] 2. 限制全局线程池
     - main.cpp 启动时 QThreadPool::globalInstance()->setMaxThreadCount(8)
     - 空闲 22 线程大部分是随核心数扩张的 QThreadPool（异步图片/Loader 解码）
     - 收益：减少空闲线程 + 每线程 1MB 栈预留；并行度略降但 UI 无感
     - 已做：main.cpp setMaxThreadCount(8)

---------------------------------------------------------------
B 组：中量级（约 10–25MB + 启动更快）
---------------------------------------------------------------
[x] 3. QML AOT 编译
     - 用 qmlcachegen / qt_add_qml_module 把绑定编译为 C++
     - 收益：QML 引擎内存显著下降（绑定不再以 JS 字符串/JIT 缓存驻留）、启动变快
     - 代价：改 CMake 结构 + 各 QML 的 import 语句 + main.cpp 加载方式，中型重构有回归风险
     - 决策点：需确认是否值得投入
     - 已做：qt_add_qml_module(URI "Beacon", RESOURCE_PREFIX "/qml", NO_RESOURCE_TARGET_PATH)
       逐文件 QT_RESOURCE_ALIAS 保持 qrc:/qml/... 布局，运行时 URL 零改动；
       qml.qrc 仅保留 /icons；qmlcachegen 生成 12 个 AOT .cpp 经 Beacon_qmlcache_loader 内嵌；
       Release 无 QT_QML_DEBUG，缓存运行期生效；已核对无 QML 报错

---------------------------------------------------------------
C 组：页面卸载（约 20–50MB，已拍板：延迟卸载）
---------------------------------------------------------------

     - 卸载后调 engine->trimComponentCache() + collectGarbage()（KernelBridge 新增
       setEngine + Q_INVOKABLE qmlCollectGarbage，防 Loader 卸载后组件缓存残留）
     - 需确认重载页（尤其 LaunchPage/InstancesPage）Component.onCompleted 不重复网络/扫描
     - 已做：main.qml activatePage + repeat Timer 置 active=false；KernelBridge qmlCollectGarbage
